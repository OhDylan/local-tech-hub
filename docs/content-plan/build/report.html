  • It's the thread through every episode: each one ends with "filed in my notebook as Must-have / Maybe / Just cool".

4.1 Project Fronkensteen: five AI personas run a house✓ verified

github.com/mmadalone/Project_Fronkensteen · HA community post "Five AI Personas Run My House from a RPi 5"
What
Five character personas, each with its own conversation agent, voice and time-of-day mood, run a house from a Raspberry Pi 5. They "argue with you about bedtime" and route notifications to the room you're in.
How
~38 pyscript Python modules (168 services) are the engine; about 80 automation and 35 script blueprints are the features; 22 Assist voice pipelines. The LLM is Extended OpenAI Conversation → Llama 4 Maverick via OpenRouter, with ElevenLabs voices. A 7-priority dispatcher picks which persona answers. A 3-layer context is built before every reply: L1 "hot" (time, presence, media), L2 "warm" (SQLite + FTS5 + sqlite-vec memory), L3 "cold" (Google Calendar, Gmail, forecasts). Aqara FP2 mmWave zones + Wi-Fi tracking tell who is in which room.
Trick
Email safety: email is attacker-controlled text reaching an agent that can call tools, so it reads subjects only by default, and a body needs an explicit follow-up. A real prompt-injection defense.
Catch
Huge scope. The author says it's in "early stages of testing" and that it has "zero lines of hand-written YAML; all code generated by Claude". It relies on paid cloud services (it tracks the budget per agent).
Twin: partlyJust cool → steal 2 ideasVideo: "A house run by five AI characters, and the one security trick worth stealing."

4.2 ZenOS-AI ("Friday's Party"): an AI that summarises your whole house✓ verified

github.com/nathan-curtis/zenos-ai · stable 2026.10.2 "Tron" · HA community thread "Friday's Party"
What
An HA-native framework for a private, context-aware assistant with a team of personas (Friday plus others), built entirely from HA Packages and scripts. No separate server.
How
Memory = "Cabinets" with "Drawers": typed, described slots inside HA, garbage-collected every 15 minutes. Each subsystem (security, water, energy…) is a component; a summariser per component writes a "Kata", and a SuperSummary combines them for Friday (diagram on page 3). Since 2026.9.0, permission grants for locks, alarm and covers need a real push to a real phone.
Trick
Pre-digest the house. The agent reads small, continuously refreshed summaries instead of hundreds of raw sensors. A new subsystem is a drawer plus a label, with no code changes.
Catch
The README warns: don't point the background summariser at a paid API, because it runs several times an hour and "will generate a significant and continuous bill". Needs a tool-calling model; very small models aren't recommended.
Twin: yes (local model)MaybeVideo: "This AI reads my whole house every few minutes, and why that would bankrupt me on a cloud API."

4.3 Guest assistant: "Where are the towels?"second-hand

r/homeassistant "Using LLMs to make a guest assistant" (Jan 2025). Read via summaries; the original wasn't reachable.
What
Guests ask the house where things are when the owners aren't around.
How
An HA script with a question field calls conversation.process on an LLM whose prompt lists items by room; a stop action returns the answer to the voice assistant that called it.
Trick
An LLM as a tool of another assistant. The main assistant hands one narrow question to a specialist prompt.
Catch
A commenter noted it's slow, because one question can trigger several model calls. The item list goes stale unless someone maintains it.
Twin: yes, easilyMust-haveVideo: "My house is the best house-sitter: ask it where anything is."

4.4 Home Generative Agent: a real agent, not a pass-through✓ verified

github.com/goruck/home-generative-agent · requires HA 2026.8+
What
Conversation, automations written from plain English and registered in HA, camera analysis, proactive alerts and long-term memory.
How
Built on LangGraph. Memory is semantic search over past conversations, stored in PostgreSQL + pgvector. "Sentinel" uses deterministic rules (not the LLM) for safety alerts such as unlocked locks and open entries. Works with OpenAI, Gemini, Anthropic or local models.
Trick
A Critical Action PIN: an AI-written automation that would unlock a door needs a PIN. Plus the clear split: rules for safety, LLM for language.
Catch
Its bundled Postgres app needs HA OS or Supervised; on HA Container (my setup) I'd run my own Postgres. It only sees entities exposed to Assist, and HA auto-exposes only certain domains (lights, switches, covers, climate, media players… plus door/lock/motion binary sensors). Everything else must be exposed by hand.
Twin: yes (chat, automations, memory)MaybeVideo: "Most 'AI home assistants' just forward your words to a chatbot. This one is a real agent."

4.5 LLM Vision: let the house see✓ verified

github.com/valentinfrlch/ha-llmvision · llmvision.org
What
Sends images, video, live feeds or Frigate events to a multimodal model, and turns the answer into text, sensor values, or a timeline of events on the dashboard. It "remembers people, pets and objects".
How
An HA integration with pluggable providers (OpenAI, Anthropic, Gemini, OpenRouter, AWS Bedrock, Azure, Groq, Ollama, LocalAI, Open WebUI…). A ready-made blueprint turns camera events into AI-summarised notifications.
Trick
"Motion detected" becomes "a courier left a parcel".
Catch
Images go to whichever provider you choose (privacy trade-off; local models are possible). HA Container needs a /media mount. It's community code: in 2026.11 it installs from the new Marketplace, which HA says is "not tested, audited, or supported" by the HA project.
Twin: yes (virtual camera)Must-have in 2028Video: "My doorbell doesn't say 'motion' any more. It says who."

4.6 Lookout: cameras as a hyper-local weather station✓ verified

github.com/wgumaa/Lookout · built on LLM Vision · HA 2025.7+
What
Reads your own outdoor cameras to estimate cloud cover, fog/haze, rain and whether the sun is visible, then exposes them as HA sensors.
How
All cameras in one LLM call per poll (every 1–30 min); polls only in daylight; a confidence score per camera. The AI is only an observer and never controls devices.
Trick
Prompt design as engineering: fog is tracked separately from cloud, rain only counts when it's actually visible, and water on the lens isn't mistaken for rain. The "Effective Sky Obstruction" output is meant to drive automatic blinds.
Catch
Needs a camera that sees the sky. The README notes some OpenAI models struggled to combine images with enforced structured output, and that older Gemini Flash models were retired.
Twin: partly (sky photos)Just cool (great teaching example)Video: "My weather forecast comes from my own window."

4.7 AI Tasks: turn any camera into a sensor (official HA)✓ verified

HA blog "Building the AI-powered local smart home" (11 Sep 2025) · AI Tasks since HA 2025.8
What
Lets any automation or template ask an AI for structured data (a number, yes/no, JSON), optionally with an image attached.
How
The official example is a template sensor that runs every 5 minutes and calls ai_task.generate_data with "How many birds are inside the coop?", requires the answer to be a number, and attaches the camera image. The result is a normal HA sensor. The blog also cites community builds such as parking-spot detection and counting chickens.
Trick
AI output forced into a schema, so ordinary automations can use it.
Catch
Every 5 minutes is about 288 model calls a day per sensor, so cost and privacy depend on how often it polls.
Twin: yesMust-have building blockVideo: "15 lines of YAML turn a camera into a 'how many…' sensor."

4.9 AI Automation Suggester: AI proposes, I decide✓ verified

github.com/ITSpecialist111/ai_automation_suggester · (HA also has a built-in Suggest button since 2025.8 that names and labels automations)
What
Looks at your entities, areas and automations, then proposes new automations as YAML.
How
Snapshot of the setup → prompt → your chosen provider (OpenAI, Anthropic, Ollama…). It never creates automations itself. Scope filters by domain/area/entity; runs on demand, on new entities, or weekly.
Trick
Human-in-the-loop by design. It's useful exactly because it can't change anything.
Catch
A cloud provider sees your entity list. Quality depends on the model and on how complete the snapshot is.
Twin: yes, idealMaybeVideo: "I let AI design the automations for a home I don't own yet."

4.10 HA Text AI: the LLM as a function call in automations✓ verified

github.com/smkrv/ha-text-ai · HA 2024.12+
What
Ask OpenAI, Anthropic, DeepSeek, Gemini or any OpenAI-compatible model from automations and scripts.
How
Per-instance conversation history (stored in a file), structured JSON output, and the full answer as a response variable, which gets around HA's 255-character state limit.
Trick
A morning briefing from forecast + sensor data, e.g. a sunscreen reminder when UV is high (an idea from the community thread; second-hand).
Catch
One more community integration to maintain; HA's built-in AI Tasks now covers part of this.
Twin: yesMaybe (compare with AI Tasks)Video: "Every morning my house writes me a briefing."

4.12 Synthetic Home + HA datasets: testing AI on homes that don't exist✓ verified

github.com/allenporter/home-assistant-synthetic-home · github.com/allenporter/home-assistant-datasets
What
Synthetic Home builds a fake home in HA from a YAML file of named devices in named areas ("like HA's demo platform, but you name devices and put them in areas"). The datasets project uses synthetic homes to evaluate AI models as HA conversation agents: generate → load → run prompts against several models → score the results.
Trick
The home is just data, so you can test AI against a home before it exists. That is exactly my situation.
Catch
A developer tool: YAML-first, no UI polish.
Twin: the foundationMust-have for S2Video: "The tool HA developers use to test AI on homes that don't exist."

5 · Season 2: the digital twin, "moving in before I have keys"

In plain words: build my future flat in software, fill it with devices that don't exist yet, have a script play "a day of me", and write down every moment I wished the house did something. That list, not guesswork, decides what I buy and build in 2028.
LayerDone when…
1 Floor planRooms, furniture and windows exported as OBJ (or GLB).
2 Virtual devicesEvery imagined device appears in its room in HA.
3 3D viewToggling a light in HA lights the room in 3D.
4 Life simulatorOne simulated day runs end to end and the automations react.
5 Living journalA ranked device wishlist and a list of renovation questions.

Honest limitation: HA uses the real clock. The script can replay a day quickly, but automations that trigger on a fixed time ("at 07:00") won't fire early. For time-lapse videos, build the twin's automations around events ("presence in the kitchen") rather than clock times, or run in real time and film a time-lapse.

Questions the twin should answer

  1. TV, projector, or neither? Do I use a living-room screen during simulated evenings?
  2. How many speakers, and where?
  3. Presence sensors: which rooms keep "losing" me?
  4. Wall panel: which dashboard views do I actually open?
  5. Guest mode: what should a guest be able to ask or do?
  6. Voice or automatic? Which things should just happen?
  7. Never automate: locks, the oven, anything safety-related.
  8. Renovation questions for a professional: extra outlets, network points, ceiling mounts.

9 · Episode 1 script draft (~60 s)

English

In 2028, I get the keys to my home.

I'm a software engineer, and I don't want a "smart home" that just turns lights on from an app.

I want a Local Tech Hub: a home where I can try every interesting piece of technology I find.

The problem? I know software. I don't know sensors, wiring, radios or home automation.

So for the next two years I'm doing this in public.

First, I'll take apart what other people have built, explain how it really works, and keep notes in a public notebook.

Then I'll build a digital twin of my home, and live in it before it exists.

By the time I get my keys, I want to know exactly what I need, and why.

This is Local Tech Hub. Episode 1.

中文

2028 年，我会拿到我家的钥匙。

我是一名软件工程师，我想要的不只是用 App 开关灯的"智能家居"。

我想把家变成一个 Local Tech Hub：一个可以实验各种有趣技术的地方。

问题是：我懂软件，但传感器、布线、无线协议、家庭自动化，我都还不懂。

所以接下来两年，我会公开记录整个过程。

第一步，拆解别人做过的有趣项目，讲清楚它到底怎么实现，然后记进我的公开笔记本。

第二步，为我的家建一个数字孪生，在它真正存在之前，先"住"进去。

等我拿到钥匙的时候，我希望清楚地知道：我需要什么，为什么需要。

这里是 Local Tech Hub。第一集。
